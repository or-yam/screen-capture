# Freeze Screen Snapshot For Region Session

Status: needs-triage
Type: AFK

## Parent

[Tahoe Native Region Capture Alignment](../../../tech-designs/tahoe-native-region-capture-alignment.md)

## What to build

Change region capture startup so the session immediately freezes the visible desktop into a snapshot-backed overlay, matching the original Lightshot interaction model. Selection, selected-region preview, annotation, copy, and save should all operate against that frozen snapshot instead of a live blurred or dimmed desktop background.

The current transparent overlay proves the app owns input, but it still leaves the user looking at live app content underneath during selection. That is the wrong UX for Lightshot parity: once capture starts, the screen should visually freeze and later app/window/content changes underneath should not affect the capture session.

## Acceptance criteria

- [ ] Starting region capture immediately captures a full-display or per-display snapshot for the active display setup.
- [ ] The overlay displays the frozen snapshot as its background instead of showing the live desktop through blur or transparency.
- [ ] Region selection, selection preview, and annotation mode operate against the same frozen snapshot-backed surface.
- [ ] App switching or content changes underneath the overlay do not change the visible capture session after it starts.
- [ ] Raw selected-region copy/export matches the frozen snapshot content the user selected.
- [ ] Annotated PNG copy/export flattens annotations over the selected crop from the frozen snapshot.
- [ ] Retina and multi-display coordinate behavior remains consistent with the global display-space selection model.
